# Signature Moment & Narrative Rhythm Contract

本文件定义：如何让整份报告拥有**有计划的视觉高潮与阅读节奏**，而不是随机出现几个漂亮组件。

---

# 1、Signature Moment 不是“每页都做 Hero”

目标：

```text
高潮
↓
解释 / 呼吸
↓
高潮
↓
分析
↓
最终收束
```

不是：

```text
30 个 Section 全部高刺激
```

也不是：

```text
30 个 Section 全部 Table / Card
```

---

# 2、生成时机

用户选择 Design Direction 后，Huashu 基于：

```text
Full Design Intent Package
+
Selected Design System Snapshot
+
Selected Design Expressiveness Profile
```

生成：

```text
workspace/signature-moment-plan.md
workspace/narrative-rhythm-map.md
```

---

# 3、Signature Candidate 来源

优先候选：

```text
OPENING
核心战略判断
关键数据代差
核心关系证明
最重要的人群 / 场景转折
最终决策 / Action Framework
```

Design Intent 的：

```text
visual_emphasis = SIGNATURE_CANDIDATE
```

只是候选，不强制 Huashu 采用固定形式。

---

# 4、最低规划要求

对于中长报告，默认至少规划：

```text
1 × Opening Moment
1~2 × Insight / Proof Moment
0~1 × Human Moment（内容适用时）
1 × Decision / Synthesis Moment
```

短报告按实际内容缩减，不为了数量强造高潮。

---

# 5、Narrative Rhythm Map

每个主要 Section 可标记：

```text
CALM
BUILD
PEAK
HOLD
RESET
```

示例：

```text
Hero                 = PEAK
Background Context   = CALM
Market Tension       = BUILD
450 vs 212           = PEAK
Detailed Tables      = RESET / CALM
Persona Story        = BUILD / PEAK
Action Framework     = HOLD / PEAK
Appendix             = CALM
```

这与 V2.7 Boldness Budget 协同，不替代它。

---

# 6、Signature Moment 的内容边界

Signature 可以放大：

```text
Scale
Contrast
Whitespace
Composition
Motion
Data Drama
Narrative Pause
```

不得放大成新的业务结论。

禁止：

```text
为了做视觉高潮，把 P1 改成 P0
为了做大数字，挑一个源里不存在的数字
为了构图完整，删除第三个关系因素
```

---

# 7、与 Report / Presentation 的关系

Report：

```text
Signature = 阅读路径中的记忆点
```

Presentation：

```text
Signature = 舞台叙事中的高潮页 / 高潮 Beat
```

两者共享 Design DNA，但不要求一模一样。

---

# 8、QA

Light Design Reflection 需要回答：

```text
计划中的 Signature 是否真正形成记忆点？
是否出现“计划 PEAK，最终仍是普通 Card Grid”？
是否高潮太多导致节奏疲劳？
是否高潮与内容重要性不匹配？
```

这是设计复盘，不允许 Reviewer 直接修改页面。
